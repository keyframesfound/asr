# TUI changes: Enter-to-download, guaranteed %/ETA, caption-only main screen

All changes are in `tui_app.py`, `engines/weights.py`, `engines/weights_worker.py`, and their tests.

## 1. Enter on an undownloaded model starts the download

`tui_app.py:803-812` (`ModelPickerScreen.on_selected`): when the selected engine is local and its weights are missing, call `self.action_download_model()` and return instead of flashing "press i to download". This reuses the existing guard logic (cloud → "no weights", already installed, "already downloading") and stays on the picker — **no auto-launch** when the download lands (the existing `_refresh_rows` "downloaded … ✓" flash already covers that moment; pressing Enter again then launches the session).

Copy updates to match the new primary key (i keeps working): row status `not installed · press i to download` → `press enter to download` (tui_app.py:776), startup flash `(default) is not installed — press i to download` → `press enter` (tui_app.py:722-723), failure row `press i to retry` → `press enter to retry` (tui_app.py:772), screen docstring (655-660). Update any tests asserting these strings.

## 2. Default model shows percentage + time remaining like the others

Root cause: `%` and `~Xm left` only render when `state.total > 0` (tui_app.py:751-762 — rendering itself is shared by all engines, no per-model branch). For the Parakeet download the total is evidently never learned (your row showed bytes only), so:

- **`engines/weights.py`** — add a HEAD-probe fallback `_probe_total_bytes(code)`: HEAD each tarball base (`_tarball_bases()`, following redirects) and return the first `Content-Length`. In `_download_worker`'s child path (tui_app run), fire it on a daemon thread right after spawning the downloader child so `total` is known within ~a second even when the streaming response is chunked / lacks Content-Length; the child's own `total` line still overwrites it when present. Keep it out of the `ASR_WEIGHTS_INPROC=1` test path so tests never touch the network.
- **Pinned sizes as last resort**: add an `EXPECTED_TARBALL_BYTES` dict in `weights.py` used when the probe fails entirely, filled at implementation time by HEAD-ing the live models-v1 tarballs. This inherits the existing "pins must stay synced after any re-pack" discipline (same as the SHA pins in `scripts/download_models.py`) — I'll update the memory note accordingly.
- **`engines/weights_worker.py:22`** — `PROGRESS_STEP_BYTES` 5 MB → 1 MB so the percentage ticks smoothly on the 0.5 s UI refresh.
- The TUI rendering code needs no change; once `total > 0` the existing `downloading… N% · speed · ~time left` line appears. Existing test `test_row_shows_percentage_speed_and_eta` keeps passing; add a unit test that the probe sets total when Content-Length is absent from the stream (mocked `urlopen`).

## 3. Listening screen: keep only the live-caption top section

Remove the scrolling transcript log and the divider; the caption stage expands to fill the freed space:

- **compose (tui_app.py:897-905)**: drop `#stage-rule` and the `#log-scroll`/`RichLog` block; keep the hidden `#partial` sink (engines still write to it for status hooks).
- **`_set_layout` (926-941)**: views become `loading | live` only; delete `_show_record_layout` and its call sites in `session_done` (1304, 1318) → `_show_live_layout()`.
- **Log writers removed**: `show_final` (1286), `session_done` log clear/writes (1293-1314, polished result now just settles into the big caption via the existing `_set_caption_indicator("final", polished)`), `_export_txt` confirmation (1233-1235 — status line already shows the saved path), `action_clear_transcript` (1190). Error status reworded (no more "full text in log" — the error shows on the status line).
- **Imports/CSS**: drop `VerticalScroll`, `RichLog`, `rich.markup.escape` (no remaining callers); delete the `#stage-rule/.rule`, `#log-scroll`, `#transcript` CSS blocks (1727-1759); `#caption-stage` height `8` → `1fr` (1699-1708) so captions fill the screen.
- **Nothing else changes**: transcript state (`_lines`, `_words`, `_audio`) is kept for Export TXT / MP3 / Copy-last / word counts; the bottom button bar stays exactly as is; `#action-bar`, key bindings, TopBar, LevelMeter untouched.
- **Tests**: rewrite `test_loading_and_record_layout_states` (tests/test_tui_chrome.py:173-212) to drop `#log-scroll` queries and the record-view section.
